## Variants

- `readable/` - for reading and changing the code: Boris, and the weak-model add-a-feature check.
- `fast/` - for running.

`fast/` is converted with `checks: off`: no null or bounds checks, so C bugs are not caught (a null access is a SIGSEGV; an out-of-bounds index reads neighbour memory; AOT keeps its range checks); use `readable/` to debug.

## Running

The modules require c2das-re's `crt` and `c_runtime` modules: a c2das-re checkout at the commit above, with the daScript its `VERSIONS.md` pins built and `scripts/build_crt.sh` run. The program reads its fixture `fixtures/test_640x360.mp4` from the Rust repository's project folder; no fixture is copied here (game data and fixtures stay with their own licenses there). With `<c2das-re>` and `<c2das>` the two checkouts:

```
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime readable/h264_file_all/h264_file_all.das -- <c2das>/tests/manual/h264bsd-mp4/fixtures/test_640x360.mp4
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime -jit fast/h264_file_all/h264_file_all.das -- <c2das>/tests/manual/h264bsd-mp4/fixtures/test_640x360.mp4
# the native build the tables compare with, in <c2das>/tests/manual/h264bsd-mp4:
clang -std=c11 -Iinclude -Iupstream/h264bsd/src -Iupstream/minimp4 -Isrc -w -O2 src/all_reference.c src/h264_file_reference_entry.c -o h264bsd-mp4
```

Its output must equal `expected.stdout` of the canonical case `h264bsd-mp4-640x360-std` in the Rust repository's `tests/canonical/cases.json`.
