# chibicc

[chibicc](https://github.com/rui314/chibicc) (Rui Ueyama, MIT), a small C11 compiler written in C,
converted to daslang by [c2das-re](https://github.com/lookibed/c2das-re). A C compiler that runs
inside daslang with no clang: the probe of c2das-re's ledger item P10.0.

This directory is a one-off publish (2026-11-22). `scripts/publish_ports.sh` does not regenerate
it; the port itself (fetch script, patch, sidecar, test) lives in c2das-re's `chibicc/` folder.

- upstream: rui314/chibicc at `90d1f7f199cc55b13c7fdb5839d1409806633fdb`
- generated by: c2das-re `796c353736540afd65f1d5bcc580cad70cdae49d`, daslang 0.6.6 at `b7d8f6f52f`,
  readable settings (`readable/chibicc.c2das`: `jit_whole_program`, nothing else)
- size: 301 functions, 9555 lines of daslang, converted in 17 s

## Files

- `readable/` - the converted program: `main.das` (the entry; chibicc's eight mutually calling C
  files as `.das.inc` fragments of one module), `host.das`, `strarray.das`, `chibicc_h.das`,
  `c_types.das`, the layout checks and the sidecar.
- `port/` - what c2das-re applies before converting: `fetch.sh` and `0001-c2das-host.patch`
  (the compiler proper runs in the driver's process instead of `fork`/`exec`; `-E` and `-S` stay,
  the assembler and linker steps are cut; a few libc calls become portable C in `host.c`;
  a numeric literal's value is a `double`).
- `LICENSE` - chibicc's MIT license; the conversion is a derived work.

## Run

The converted compiler needs c2das-re's runtime modules (`c_runtime/`, `dasCRuntime/`) and runs in
a chibicc checkout, where `include/` holds chibicc's own headers:

```
cd chibicc/fetch/chibicc          # made by c2das-re's chibicc/fetch.sh
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime \
    <this dir>/readable/main.das -- -S -o out.s input.c      # or -E; add -jit after daslang for the JIT
```

## Results (c2das-re's probe, box PC, 2026-11-22)

The oracle is native chibicc built from the same patched sources with `-funsigned-char` and full
source paths (the converter's dialect). Output file, stderr and exit code are compared.

| corpus | `-S` | `-E` | tiers |
| :-- | --: | --: | :-- |
| c-testsuite, 220 files | 220 / 220 | 220 / 220 | interpreter and JIT |
| PureDOOM, 62 units | 62 / 62 | 62 / 62 | interpreter and JIT |
| gcc-torture, 1204 tests | 1200 / 1204 | - | interpreter and JIT |

The four gcc-torture differences are tests where native chibicc itself crashes.

Preprocessor speed, `-E` over the 62 PureDOOM units (614 580 tokens, counted by a regular
tokenizer over native's output; CPU time inside the compiler, exclusive quiet runs):

| tier | tokens per second | x native |
| :-- | --: | --: |
| native, `-O2` | 1.96 M | 1.0 |
| daslang JIT | 784 k | 2.5 |
| daslang interpreter | 121 k | 16 |
| daslang wasm64 interpreter (node) | 29.4 k | 67 |

Start-up on an empty file: native 2.3 ms, interpreter 0.61 s, JIT 0.72 s with a warm cache,
wasm64 interpreter 9.1 s.

What this compiler is not: it emits x86-64 assembly, not c2das-re's C-IR. Its parser lowers
expressions as it reads them (`a[i]`, `x++`, `sizeof`, typedef names), so its AST does not carry
what the C-IR records; the lexer, preprocessor and declaration parser are the reusable parts.
