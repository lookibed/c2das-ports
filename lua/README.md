# lua

Lua 5.4.8 converted to daslang by [c2das-re](https://github.com/lookibed/c2das-re). Everything in this directory is generated by `scripts/publish_ports.sh --program lua --no-convert --perf --samples 3 --lanes interp,jit,exe,jit-goto,interp-source-cut,jit-source-cut,interp-single,jit-single --timeout 1800` in c2das-re; never edit it, a fix belongs in c2das-re.

## Files

- `lua/` - the interpreter `lua`: the core, the standard libraries and `lua.c`, converted as a module per C file, every cycle of files one module of `.das.inc` fragments (c2das-re's source layout, its default; `lua/program.layout.txt` lists the modules); `lua/lua.das` holds `main`.
- `luac/` - the compiler `luac`: the core, the auxiliary library and `luac.c`, converted as a module per C file, every cycle of files one module of `.das.inc` fragments (c2das-re's source layout, its default; `luac/program.layout.txt` lists the modules); `luac/luac.das` holds `main`.
- `source-cut/lua/` - the same program with the cycles among files cut by late binding through `source-cut/lua/lua_link.das` (c2das-re's `--layout source-cut`; its `program.layout.txt` lists the cut).
- `source-cut/luac/` - the same program with the cycles among files cut by late binding through `source-cut/luac/luac_link.das` (c2das-re's `--layout source-cut`; its `program.layout.txt` lists the cut).
- `single/lua.das` - the same program as one module (c2das-re's `--layout single`).
- `single/luac.das` - the same program as one module (c2das-re's `--layout single`).
- `lua.c2das` - the sidecar both were converted under.
- `LICENSE` - Lua's license, from `src/lua.h` of the release; the conversion is a derived work.
- `bench/` - the benchmark scripts the tables below run, and `timed.lua`, which runs each and reports its work seconds measured inside the process.
- `perf/capture_*.json` - every capture the tables were rendered from, every sample of every lane.

## Running

The modules require c2das-re's `crt` and `c_runtime` modules: a c2das-re checkout at the commit above, with the daScript its `VERSIONS.md` pins built and `scripts/build_crt.sh` run. With `<c2das-re>` that checkout:

```
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime lua/lua.das -- -e "print(1+1)"
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime -jit lua/lua.das -- bench/fib.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime -exe lua/lua.das -output lua && ./lua bench/fib.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime luac/luac.das -- -o out.luac script.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime single/lua.das -- -e "print(1+1)"
```

Everything after `--` is the program's own command line; daslang writes the `-exe` binary at the `-output` path as given.

## Upstream tests

The results c2das-re's P5.1 recorded for this program, not results of this publish's run; the perf section's test-suite row runs the release's test suite once the perf tables are on:

- `lua -e "print(1+1)"` and a script over string, table and math print what the native build prints, under the interpreter and the JIT.
- `luac -o` writes the native build's bytecode byte for byte for every file of the release's test suite.
- A Lua error is caught as the native build catches it under the interpreter (`pcall`, `xpcall`, nested protected calls, errors in coroutines); under the JIT a protected call reports success and an uncaught error exits 0 with no message (c2das-re's `docs/probe-findings.md` F75, lookibed/daScript#30). ## Performance

Captured 2026-11-10 08:43 UTC on x86_64, PC (AMD Ryzen 7 7435HS); clang version 22.1.8 (https://github.com/llvm/llvm-project ca7933e47d3a3451d81e72ac174dcb5aa28b59d1) at `/root/libclang/bin/clang`, the native lane's compiler; daslang 0.6.5; c2das-re `852c24fd4d0cd22d04faa908173345c3f79cfc82`. Reproduced by `scripts/publish_ports.sh --program lua --no-convert --perf --samples 3 --lanes interp,jit,exe,jit-goto,interp-source-cut,jit-source-cut,interp-single,jit-single --timeout 1800 --box PC`. A sample is one run of the whole program, its own process spawned by the publisher (the spawn included); a cell is the median of 3 samples, ± half their range as a share of the median; a run past 1800 s fails its cell. A das lane's cell stands only when every run prints what the native build prints and exits as it does (the test-suite row compares the exit code and requires the line the suite prints after its last test passes, not the output: it prints its random seeds and timings). A lane the run left out is `not measured`. The JIT, goto dispatch lane runs the JIT over the source layout converted with c2das-re's `--switch-dispatch goto`, a dense switch (the interpreter's dispatch among them) as a jump table; the modules published here are the default conversion, and the lane's command below names the one that regenerates its tree. The AOT lane is measured only when asked for and has a column only where its build stood.

Every speed number is the work alone, timed inside the process: a workload runs under `bench/timed.lua`, which reads `os.clock()` (C `clock()`, the process's CPU time, under every lane) before and after the script and reports the seconds between, and its work time is the median of those, ± half their range as a share of it. The work seconds are process CPU time (`clock()`, user plus system), not dasProfile's steady wall clock, since stock Lua has no in-process wall clock finer than `os.time()`'s whole seconds. A cell without them (a capture made before the wrapper) is `(by subtraction)`, its work time the cell less the same lane's `startup` cell, the run that loads the program and does no work, ± the two cells' half ranges as a share of the work time, and the mark follows it into every ratio and mean; one not above 0 is `within the start`, and a lane whose startup cell does not stand has none. The startup cells stand alone in the startup table, their ratio to native's with them, in no other ratio or mean; the times table holds the raw medians, the start included. A cell or a work time whose spread is above 20% is `suspect`: its spread alone, no ratio, and out of the projects table's means; a suspect startup cell makes every work time of its lane by subtraction `suspect (startup)`.
