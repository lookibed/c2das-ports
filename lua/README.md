# lua

Lua 5.4.8 converted to daslang by [c2das-re](https://github.com/lookibed/c2das-re). Everything in this directory is generated by `scripts/publish_ports.sh --program lua --perf --samples 3 --lanes interp,jit,exe,aot,interp-source-cut,jit-source-cut,interp-single,jit-single --timeout 1800` in c2das-re; never edit it, a fix belongs in c2das-re.

## Files

- `lua/` - the interpreter `lua`: the core, the standard libraries and `lua.c`, converted as a module per C file, every cycle of files one module of `.das.inc` fragments (c2das-re's source layout, its default; `lua/program.layout.txt` lists the modules); `lua/lua.das` holds `main`.
- `luac/` - the compiler `luac`: the core, the auxiliary library and `luac.c`, converted as a module per C file, every cycle of files one module of `.das.inc` fragments (c2das-re's source layout, its default; `luac/program.layout.txt` lists the modules); `luac/luac.das` holds `main`.
- `source-cut/lua/` - the same program with the cycles among files cut by late binding through `source-cut/lua/lua_link.das` (c2das-re's `--layout source-cut`; its `program.layout.txt` lists the cut).
- `source-cut/luac/` - the same program with the cycles among files cut by late binding through `source-cut/luac/luac_link.das` (c2das-re's `--layout source-cut`; its `program.layout.txt` lists the cut).
- `single/lua.das` - the same program as one module (c2das-re's `--layout single`).
- `single/luac.das` - the same program as one module (c2das-re's `--layout single`).
- `lua.c2das` - the sidecar both were converted under.
- `LICENSE` - Lua's license, from `src/lua.h` of the release; the conversion is a derived work.
- `bench/` - the benchmark scripts the tables below run.
- `perf/capture_*.json` - every capture the tables were rendered from, every sample of every lane.

## Running

The modules require c2das-re's `crt` and `c_runtime` modules: a c2das-re checkout at the commit above, with the daScript its `VERSIONS.md` pins built and `scripts/build_crt.sh` run. With `<c2das-re>` that checkout:

```
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime lua/lua.das -- -e "print(1+1)"
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime -jit lua/lua.das -- bench/fib.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime -exe lua/lua.das -output lua && ./lua.exe bench/fib.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime luac/luac.das -- -o out.luac script.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime single/lua.das -- -e "print(1+1)"
```

Everything after `--` is the program's own command line; daslang names the `-exe` binary with `.exe` on every platform.

## Upstream tests

The results c2das-re's P5.1 recorded for this program, not results of this publish's run; the perf section's test-suite row runs the release's test suite once the perf tables are on:

- `lua -e "print(1+1)"` and a script over string, table and math print what the native build prints, under the interpreter and the JIT.
- `luac -o` writes the native build's bytecode byte for byte for every file of the release's test suite.
- A Lua error is caught as the native build catches it under the interpreter (`pcall`, `xpcall`, nested protected calls, errors in coroutines); under the JIT a protected call reports success and an uncaught error exits 0 with no message (c2das-re's `docs/probe-findings.md` F75, lookibed/daScript#30). Lua's own test suite passes under the interpreter, file by file and as one process (c2das-re's P5.3 and P5.4).

## Performance

Captured 2026-11-04 02:55 UTC on x86_64, PC (AMD Ryzen 7 7435HS); clang version 22.1.8 (https://github.com/llvm/llvm-project ca7933e47d3a3451d81e72ac174dcb5aa28b59d1) at `/root/libclang/bin/clang`, the native lane's compiler; daslang 0.6.4; c2das-re `61aa9c181cf8c528d7a5ec19edad79c8ad4af04e`. Reproduced by `scripts/publish_ports.sh --program lua --perf --samples 3 --lanes interp,jit,exe,aot,interp-source-cut,jit-source-cut,interp-single,jit-single --timeout 1800 --box PC`. A sample is one run of the whole program, its own process spawned by the publisher (the spawn included); a cell is the median of 3 samples, ± half their range as a share of the median; a run past 1800 s fails its cell. A das lane's cell stands only when every run prints what the native build prints and exits as it does (the test-suite row compares the exit code and requires the line the suite prints after its last test passes, not the output: it prints its random seeds and timings). A lane the run left out is `not measured`.

Every speed number is the work alone: a workload's work time under a lane is its cell less the same lane's `startup` cell, the run that loads the program and does no work (under a das lane, the load from the module cache an unmeasured run left in the folder), ± the two cells' half ranges as a share of the work time; one not above 0 is `within the start`, and a lane whose startup cell does not stand has none. The startup cells stand alone in the startup table, their ratio to native's with them, in no other ratio or mean; the times table holds the raw medians, the start included. A cell or a work time whose spread is above 20% is `suspect`: its spread alone, no ratio, and out of the projects table's means; a suspect startup cell makes every work time of its lane `suspect (startup)`.
