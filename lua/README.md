# lua

Lua 5.4.8 converted to daslang by [c2das-re](https://github.com/lookibed/c2das-re). Everything in this directory is generated by `scripts/publish_ports.sh --program lua --perf --samples 5 --lanes interp,jit,exe,aot --timeout 1800` in c2das-re; never edit it, a fix belongs in c2das-re.

## Files

- `lua_all.das` - the interpreter `lua`: the core, the standard libraries and `lua.c` as one translation unit, converted.
- `luac_all.das` - the compiler `luac`: the core, the auxiliary library and `luac.c` as one translation unit, converted.
- `lua.c2das` - the sidecar both were converted under.
- `LICENSE` - Lua's license, from `src/lua.h` of the release; the conversion is a derived work.
- `bench/` - the benchmark scripts the tables below run.
- `perf/capture_*.json` - every capture the tables were rendered from, every sample of every lane.

## Running

The modules require c2das-re's `crt` and `c_runtime` modules: a c2das-re checkout at the commit above, with the daScript its `VERSIONS.md` pins built and `scripts/build_crt.sh` run. With `<c2das-re>` that checkout:

```
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime lua_all.das -- -e "print(1+1)"
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime -jit lua_all.das -- bench/fib.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime -exe lua_all.das -output lua && ./lua.exe bench/fib.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime luac_all.das -- -o out.luac script.lua
```

Everything after `--` is the program's own command line; daslang names the `-exe` binary with `.exe` on every platform.

## Performance

Captured 2026-10-23 12:57 UTC on x86_64, AMD FX(tm)-6300 Six-Core Processor; clang version 22.1.8 (https://github.com/llvm/llvm-project ca7933e47d3a3451d81e72ac174dcb5aa28b59d1) at `/root/libclang/bin/clang`, the native lane's compiler; daslang 0.6.4; c2das-re `afbc38936bd81e9f9e6b5f3de79165da5f47fb5a`. Reproduced by `scripts/publish_ports.sh --program lua --perf --samples 5 --lanes interp,jit,exe,aot --timeout 1800`. A cell is the median wall time of 5 runs of the whole program, each its own process spawned by the publisher (the spawn included), ± half the range of the samples as a share of the median; a run past 1800 s fails its cell. The `startup` row runs no work: under a das lane it is the module's load from the cache an unmeasured run of the same arguments left in the folder (a cache load, not a compile), which every other row of that lane includes, so a workload's own time is its cell less the startup cell, and the row is an upper bound of the load. A das lane's cell stands only when every run prints what the native build prints and exits as it does (the test-suite row compares the exit code alone: it prints its random seeds and timings). A lane the run left out is `not measured`.
