# lua

Lua 5.4.8 converted to daslang by [c2das-re](https://github.com/lookibed/c2das-re). Everything in this directory is generated by `scripts/publish_ports.sh --program lua --perf --samples 5 --lanes interp,jit,exe,aot,interp-scc,jit-scc,interp-single,jit-single --timeout 1800` in c2das-re; never edit it, a fix belongs in c2das-re.

## Files

- `lua/` - the interpreter `lua`: the core, the standard libraries and `lua.c`, converted as a module per C file, the cycles among files cut by late binding through `lua/lua_link.das` (c2das-re's source layout, its default; `lua/program.layout.txt` lists the cut); `lua/lua.das` holds `main`.
- `luac/` - the compiler `luac`: the core, the auxiliary library and `luac.c`, converted as a module per C file, the cycles among files cut by late binding through `luac/luac_link.das` (c2das-re's source layout, its default; `luac/program.layout.txt` lists the cut); `luac/luac.das` holds `main`.
- `scc/lua/` - the same program with every cycle of files one module of `.das.inc` fragments (c2das-re's `--layout scc`).
- `scc/luac/` - the same program with every cycle of files one module of `.das.inc` fragments (c2das-re's `--layout scc`).
- `single/lua.das` - the same program as one module (c2das-re's `--layout single`).
- `single/luac.das` - the same program as one module (c2das-re's `--layout single`).
- `lua.c2das` - the sidecar both were converted under.
- `LICENSE` - Lua's license, from `src/lua.h` of the release; the conversion is a derived work.
- `bench/` - the benchmark scripts the tables below run.
- `perf/capture_*.json` - every capture the tables were rendered from, every sample of every lane.

## Running

The modules require c2das-re's `crt` and `c_runtime` modules: a c2das-re checkout at the commit above, with the daScript its `VERSIONS.md` pins built and `scripts/build_crt.sh` run. With `<c2das-re>` that checkout:

```
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime lua/lua.das -- -e "print(1+1)"
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime -jit lua/lua.das -- bench/fib.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime -exe lua/lua.das -output lua && ./lua.exe bench/fib.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime luac/luac.das -- -o out.luac script.lua
daslang -load_module <c2das-re>/dasCRuntime -load_module <c2das-re>/c_runtime single/lua.das -- -e "print(1+1)"
```

Everything after `--` is the program's own command line; daslang names the `-exe` binary with `.exe` on every platform.

## Upstream tests

The results c2das-re's P5.1 recorded for this program, not results of this publish's run; the perf section's test-suite row runs the release's test suite once the perf tables are on:

- `lua -e "print(1+1)"` and a script over string, table and math print what the native build prints, under the interpreter and the JIT.
- `luac -o` writes the native build's bytecode byte for byte for every file of the release's test suite.
- A Lua error is caught as the native build catches it under the interpreter (`pcall`, `xpcall`, nested protected calls, errors in coroutines); under the JIT a protected call reports success and an uncaught error exits 0 with no message (c2das-re's `docs/probe-findings.md` F75, lookibed/daScript#30). Lua's own test suite passes under the interpreter, file by file and as one process (c2das-re's P5.3 and P5.4).

## Performance

Captured 2026-10-31 23:48 UTC on x86_64, AMD FX(tm)-6300 Six-Core Processor; clang version 22.1.8 (https://github.com/llvm/llvm-project ca7933e47d3a3451d81e72ac174dcb5aa28b59d1) at `/root/libclang/bin/clang`, the native lane's compiler; daslang 0.6.4; c2das-re `47779a151a4f81fd4c798fe8d8d11682c1e87b90`. Reproduced by `scripts/publish_ports.sh --program lua --perf --samples 5 --lanes interp,jit,exe,aot,interp-scc,jit-scc,interp-single,jit-single --timeout 1800`. A cell is the median wall time of 5 runs of the whole program, each its own process spawned by the publisher (the spawn included), ± half the range of the samples as a share of the median; a run past 1800 s fails its cell. The `startup` row runs no work: under a das lane it is the module's load from the cache an unmeasured run of the same arguments left in the folder (a cache load, not a compile), which every other row of that lane includes, so a workload's own time is its cell less the startup cell, and the row is an upper bound of the load. A das lane's cell stands only when every run prints what the native build prints and exits as it does (the test-suite row compares the exit code and requires the line the suite prints after its last test passes, not the output: it prints its random seeds and timings). A lane the run left out is `not measured`.
